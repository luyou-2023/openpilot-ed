# OpenPilot 详细设计文档

## 1. Manager模块详细设计

### 1.1 模块概述

Manager模块是OpenPilot系统的核心进程管理器，负责系统的初始化、进程生命周期管理和状态转换。

**文件位置**：`system/manager/manager.py`

### 1.2 核心功能

#### 1.2.1 系统初始化（manager_init）

**功能**：完成系统启动前的所有初始化工作

**主要步骤**：
1. **保存启动日志**：调用`save_bootlog()`保存系统启动日志
2. **参数清理**：根据不同的参数类型清理旧参数
   - `CLEAR_ON_MANAGER_START`：管理器启动时清理
   - `CLEAR_ON_ONROAD_TRANSITION`：上路时清理
   - `CLEAR_ON_OFFROAD_TRANSITION`：下路时清理
3. **默认参数设置**：为未设置的参数设置默认值
   - `OpenpilotEnabledToggle`：默认启用openpilot
   - `LongitudinalPersonality`：纵向控制个性（标准/激进/保守）
   - `IsMetric`：使用公制单位
   - `ExperimentalMode`：实验模式开关
4. **设备注册**：调用`register()`注册设备，获取dongle_id
5. **日志初始化**：初始化Sentry错误追踪和云日志
6. **进程预导入**：预导入所有进程模块，加快启动速度

#### 1.2.2 进程管理（manager_thread）

**功能**：主循环，持续监控和管理所有进程

**工作流程**：
1. **订阅关键消息**：订阅`deviceState`和`carParams`
2. **状态检测**：检测系统是否处于"started"状态
3. **进程启动控制**：
   - 根据`started`状态决定启动哪些进程
   - 忽略列表中的进程不会启动（如loggerd在LoggerEnable关闭时）
4. **进程监控**：定期检查进程运行状态
5. **状态发布**：发布`managerState`消息，包含所有进程状态

**关键逻辑**：
```python
# 根据状态决定启动哪些进程
ensure_running(managed_processes.values(), started, params=params, CP=sm['carParams'], not_run=ignore)
```

#### 1.2.3 进程配置（process_config.py）

**功能**：定义所有系统进程及其启动条件

**进程类型**：
- **DaemonProcess**：守护进程（如manage_athenad）
- **NativeProcess**：C++编译的本地进程（如camerad、modeld）
- **PythonProcess**：Python进程（如controlsd、plannerd）

**启动条件函数**：
- `always_run`：始终运行
- `only_onroad`：仅在上路时运行
- `only_offroad`：仅在下路时运行
- `driverview`：驾驶员视角模式
- `iscar`：真实车辆模式
- `notcar`：非车辆模式（测试）

**关键进程列表**：
- `camerad`：摄像头数据采集
- `modeld`：深度学习模型推理
- `controlsd`：控制决策
- `plannerd`：路径规划
- `card`：车辆接口
- `loggerd`：数据记录
- `ui`：用户界面

### 1.3 状态管理

#### 1.3.1 状态转换

系统在以下状态间转换：
- **Offroad**：系统未启动，车辆未行驶
- **Onroad**：系统启动，车辆行驶中

**状态转换触发**：
- `deviceState.started`：设备状态变化
- 参数变化：某些参数变化会触发状态转换

#### 1.3.2 参数管理

**参数类型**：
- `CLEAR_ON_MANAGER_START`：管理器启动时清理
- `CLEAR_ON_ONROAD_TRANSITION`：上路时清理
- `CLEAR_ON_OFFROAD_TRANSITION`：下路时清理
- `DEVELOPMENT_ONLY`：仅开发模式

**参数存储**：使用`Params`类管理，存储在`/data/params`目录

### 1.4 错误处理

#### 1.4.1 进程崩溃处理

- 自动检测进程崩溃
- 自动重启崩溃的进程
- 记录崩溃日志

#### 1.4.2 系统关闭

支持三种关闭方式：
- `DoUninstall`：卸载系统
- `DoReboot`：重启设备
- `DoShutdown`：关闭设备

## 2. Controls模块详细设计

### 2.1 模块概述

Controls模块是OpenPilot的核心控制决策模块，负责状态机管理、事件处理、纵向和横向控制协调。

**文件位置**：`selfdrive/controls/controlsd.py`

### 2.2 核心类：Controls

#### 2.2.1 初始化（__init__）

**主要组件初始化**：

1. **车辆接口**：
   ```python
   self.CI = get_car_interface(self.CP)  # 车辆接口
   self.CP = CarParams  # 车辆参数
   ```

2. **消息通道**：
   - `PubMaster`：发布`controlsState`、`carControl`、`onroadEvents`
   - `SubMaster`：订阅传感器、摄像头、车辆状态等消息

3. **控制算法**：
   - `LongControl`：纵向控制（速度、加速度）
   - `LatControl`：横向控制（转向）
     - `LatControlPID`：PID控制
     - `LatControlAngle`：角度控制
     - `LatControlTorque`：扭矩控制

4. **事件系统**：
   - `AlertManager`：警报管理
   - `Events`：事件处理

5. **状态变量**：
   - `state`：当前状态（disabled/enabled/softDisabling等）
   - `enabled`：是否启用
   - `active`：是否激活

#### 2.2.2 数据采样（data_sample）

**功能**：从消息队列接收数据并更新状态

**处理流程**：
1. 接收`carState`消息
2. 更新`SubMaster`中的所有订阅消息
3. 检查初始化状态：
   - 等待所有消息有效
   - 检查摄像头流可用性
   - 设置初始化标志

**关键逻辑**：
```python
if not self.initialized:
    all_valid = CS.canValid and self.sm.all_checks()
    if all_valid or timed_out:
        self.initialized = True
```

#### 2.2.3 事件更新（update_events）

**功能**：根据车辆状态和系统状态生成事件

**事件类型**：
- **NO_ENTRY**：禁止进入（系统不可用）
- **SOFT_DISABLE**：软禁用（给用户3秒接管时间）
- **IMMEDIATE_DISABLE**：立即禁用
- **USER_DISABLE**：用户禁用
- **PRE_ENABLE**：预启用
- **ENABLE**：启用
- **WARNING**：警告

**事件检测**：
1. **硬件故障**：
   - 摄像头故障：`EventName.cameraMalfunction`
   - 雷达故障：`EventName.radarFault`
   - USB错误：`EventName.usbError`
   - CAN总线错误：`EventName.canError`

2. **系统状态**：
   - 过热：`EventName.overheat`
   - 存储空间不足：`EventName.outOfSpace`
   - 内存不足：`EventName.lowMemory`
   - 进程未运行：`EventName.processNotRunning`

3. **车辆状态**：
   - 校准未完成：`EventName.calibrationIncomplete`
   - 巡航不匹配：`EventName.cruiseMismatch`
   - 转向饱和：`EventName.steerSaturated`

4. **安全相关**：
   - 前向碰撞预警：`EventName.fcw`
   - 车道偏离：`EventName.ldw`
   - 控制不匹配：`EventName.controlsMismatch`

### 2.3 状态机设计

#### 2.3.1 状态定义

```python
State.disabled      # 禁用状态
State.preEnabled    # 预启用状态
State.enabled       # 启用状态
State.softDisabling # 软禁用中
State.overriding    # 覆盖控制状态
```

#### 2.3.2 状态转换（state_transition）

**转换规则**：

1. **从disabled转换**：
   - 收到`ENABLE`事件 → `enabled`或`preEnabled`或`overriding`
   - 如果有`NO_ENTRY`事件，保持`disabled`

2. **从enabled转换**：
   - 收到`SOFT_DISABLE` → `softDisabling`
   - 收到`OVERRIDE_LATERAL/LONGITUDINAL` → `overriding`
   - 收到`IMMEDIATE_DISABLE`或`USER_DISABLE` → `disabled`

3. **从softDisabling转换**：
   - 如果`SOFT_DISABLE`事件消失 → `enabled`
   - 如果计时器到期（3秒） → `disabled`

4. **从overriding转换**：
   - 如果覆盖事件消失 → `enabled`
   - 如果收到`SOFT_DISABLE` → `softDisabling`

**软禁用机制**：
- 软禁用计时器：3秒（`SOFT_DISABLE_TIME`）
- 给用户时间接管控制
- 计时器到期后进入禁用状态

### 2.4 控制算法

#### 2.4.1 状态控制（state_control）

**功能**：根据当前状态生成控制命令

**处理流程**：

1. **更新车辆模型参数**：
   ```python
   self.VM.update_params(stiffnessFactor, steerRatio)
   ```

2. **更新扭矩参数**（如果使用扭矩控制）：
   ```python
   if self.CP.lateralTuning.which() == 'torque':
       self.LaC.update_live_torque_params(...)
   ```

3. **计算纵向控制**：
   ```python
   actuators.accel = self.LoC.update(CC.longActive, CS, long_plan.aTarget, ...)
   ```

4. **计算横向控制**：
   ```python
   actuators.steer, actuators.steeringAngleDeg, lac_log = \
       self.LaC.update(CC.latActive, CS, self.VM, ...)
   ```

5. **处理转向饱和**：
   - 检测转向是否达到极限
   - 如果饱和且偏离路径，触发`steerSaturated`事件

6. **验证控制值**：
   - 确保所有控制值都是有限数（非NaN/Inf）
   - 异常值重置为0

#### 2.4.2 纵向控制（LongControl）

**文件位置**：`selfdrive/controls/lib/longcontrol.py`

**状态机**：
- `off`：关闭
- `stopping`：停止中
- `starting`：启动中
- `pid`：PID控制中

**控制逻辑**：
1. **PID控制器**：
   - 输入：目标加速度 - 当前加速度
   - 输出：控制加速度
   - 前馈：目标加速度

2. **状态转换**：
   - `stopping`：当需要停止时，逐渐减小加速度
   - `starting`：启动时使用固定加速度
   - `pid`：正常PID控制

3. **加速度限制**：
   - 最大加速度：根据速度动态调整
   - 最小加速度：-4.0 m/s²

#### 2.4.3 横向控制（LatControl）

**基类**：`selfdrive/controls/lib/latcontrol.py`

**子类实现**：

1. **LatControlPID**（PID控制）：
   - 输入：期望转向角 - 当前转向角
   - 输出：转向扭矩
   - 前馈：基于速度的转向前馈

2. **LatControlAngle**（角度控制）：
   - 直接控制转向角度
   - 适用于支持角度控制的车辆

3. **LatControlTorque**（扭矩控制）：
   - 基于横向加速度控制
   - 考虑摩擦和重力补偿
   - 使用实时校准的扭矩参数

**饱和检测**：
- 检测转向是否达到极限
- 如果持续饱和，触发警告

## 3. ModelD模块详细设计

### 3.1 模块概述

ModelD模块负责运行深度学习模型（Supercombo），从摄像头图像中提取驾驶相关信息。

**文件位置**：`selfdrive/modeld/modeld.py`

### 3.2 模型架构

#### 3.2.1 模型输入

**图像输入**：
- **主摄像头**：256×512像素，YUV420格式，6通道
  - 通道0-3：Y通道（下采样）
  - 通道4：U通道（半分辨率）
  - 通道5：V通道（半分辨率）
- **广角摄像头**：可选，格式同主摄像头

**历史输入**：
- **desire**：期望动作（100帧历史，8维one-hot）
- **traffic_convention**：交通规则（2维，左/右行）
- **lateral_control_params**：横向控制参数（速度、延迟）
- **prev_desired_curv**：历史期望曲率（100帧）
- **features_buffer**：特征缓冲区（99帧，每帧512维）

#### 3.2.2 模型输出

**路径规划**（plan）：
- 位置（position.x, position.y）
- 速度（velocity.x）
- 加速度（acceleration.x）
- 时间索引：32个时间点（0-10秒）

**车道线**（lane_lines）：
- 4条车道线
- 每条包含位置、置信度等信息

**道路边缘**（road_edges）：
- 2条道路边缘线

**目标检测**（lead）：
- 前车检测和跟踪
- 位置、速度、加速度预测

**姿态估计**（pose）：
- 车辆姿态（位置、旋转）
- 道路变换矩阵

**元数据**（meta）：
- 期望状态（desireState）
- 车道变更状态
- 硬制动预测

### 3.3 模型推理流程

#### 3.3.1 初始化

1. **创建OpenCL上下文**：
   ```python
   cl_context = CLContext()
   ```

2. **加载模型**：
   ```python
   model = ModelState(cl_context)
   ```
   - 加载模型文件（.thneed或.onnx）
   - 初始化输入输出缓冲区
   - 加载模型元数据

3. **连接摄像头流**：
   ```python
   vipc_client_main = VisionIpcClient("camerad", ...)
   vipc_client_extra = VisionIpcClient("camerad", ...)
   ```

#### 3.3.2 推理循环

**主循环步骤**：

1. **接收图像帧**：
   ```python
   buf_main = vipc_client_main.recv()
   buf_extra = vipc_client_extra.recv()
   ```

2. **同步帧**：
   - 确保主摄像头和广角摄像头帧同步
   - 检查时间戳差异

3. **准备输入**：
   - 更新desire输入（脉冲触发）
   - 更新traffic_convention
   - 更新lateral_control_params
   - 准备图像变换矩阵

4. **执行推理**：
   ```python
   model_output = model.run(buf_main, buf_extra, transform_main, transform_extra, inputs)
   ```

5. **解析输出**：
   - 使用`Parser`解析模型原始输出
   - 应用softmax、sigmoid等激活函数
   - 处理混合密度网络（MDN）输出

6. **更新历史状态**：
   - 更新features_buffer
   - 更新prev_desired_curv

7. **发布消息**：
   - `modelV2`：模型推理结果
   - `drivingModelData`：驾驶模型数据
   - `cameraOdometry`：相机里程计

### 3.4 模型输出处理

#### 3.4.1 输出解析（Parser）

**文件位置**：`selfdrive/modeld/parse_model_outputs.py`

**解析类型**：

1. **混合密度网络（MDN）**：
   - 用于路径规划、车道线等
   - 输出多个假设（hypotheses）和权重
   - 选择最佳假设

2. **分类输出**：
   - 使用softmax归一化
   - 用于期望状态、车道线概率等

3. **二分类输出**：
   - 使用sigmoid激活
   - 用于前车概率、元数据等

#### 3.4.2 消息填充（fill_model_msg）

**功能**：将解析后的模型输出填充到消息中

**主要内容**：
- 路径点（position, velocity, acceleration）
- 车道线（laneLines）
- 道路边缘（roadEdges）
- 前车信息（leads）
- 期望曲率（desiredCurvature）
- 元数据（meta）

### 3.5 性能优化

#### 3.5.1 帧率控制

- 目标帧率：20Hz（50ms周期）
- 使用`Ratekeeper`控制执行频率
- 跳过掉帧，避免累积延迟

#### 3.5.2 GPU加速

- 使用OpenCL进行图像预处理
- 模型推理在GPU上执行
- 零拷贝内存传输

#### 3.5.3 掉帧处理

- 检测VIPC掉帧
- 如果掉帧，只准备输入不执行推理
- 记录掉帧率用于监控

## 4. PlannerD模块详细设计

### 4.1 模块概述

PlannerD模块负责纵向速度规划，使用模型预测控制（MPC）算法优化速度轨迹。

**文件位置**：`selfdrive/controls/plannerd.py`

### 4.2 核心类：LongitudinalPlanner

#### 4.2.1 初始化

**主要组件**：
- `LongitudinalMpc`：MPC控制器
- `v_desired_filter`：期望速度滤波器
- 轨迹缓冲区：速度、加速度、加加速度轨迹

#### 4.2.2 更新流程（update）

**输入处理**：
1. **解析模型输出**：
   ```python
   x, v, a, j = self.parse_model(sm['modelV2'], self.v_model_error)
   ```
   - 从modelV2中提取路径规划信息
   - 插值到MPC时间索引
   - 补偿模型速度误差

2. **速度限制**：
   - 根据当前速度计算最大加速度
   - 考虑转弯时的横向加速度限制
   - 应用加速度限制

3. **状态重置**：
   - 如果纵向控制关闭或用户控制速度，重置状态
   - 如果车辆静止，重置状态

4. **MPC优化**：
   ```python
   self.mpc.update(sm, v_cruise, x, v, a, j, personality)
   ```
   - 设置MPC权重（根据个性）
   - 设置加速度限制
   - 设置当前状态
   - 执行优化

5. **轨迹生成**：
   - 从MPC解中提取速度、加速度、加加速度轨迹
   - 插值到控制时间索引

#### 4.2.3 模型解析（parse_model）

**功能**：从modelV2消息中提取路径规划信息

**处理步骤**：
1. 验证模型输出维度
2. 从模型时间索引插值到MPC时间索引
3. 补偿模型速度误差
4. 计算加加速度（jerk）

**时间索引**：
- 模型时间索引：32个点（0-10秒）
- MPC时间索引：12个点（0-10秒，非线性分布）

### 4.3 MPC控制器设计

#### 4.3.1 MPC模型（LongitudinalMpc）

**文件位置**：`selfdrive/controls/lib/longitudinal_mpc_lib/long_mpc.py`

**状态变量**：
- `x_ego`：自车位置
- `v_ego`：自车速度
- `a_ego`：自车加速度

**控制变量**：
- `j_ego`：加加速度（jerk）

**参数**：
- 前车信息（位置、速度、加速度）
- 巡航速度
- 加速度限制

#### 4.3.2 成本函数

**主要成本项**：

1. **位置成本**：
   - `X_EGO_OBSTACLE_COST`：与前车距离成本
   - `X_EGO_COST`：位置跟踪成本

2. **速度成本**：
   - `V_EGO_COST`：速度跟踪成本

3. **加速度成本**：
   - `A_EGO_COST`：加速度平滑成本
   - `A_CHANGE_COST`：加速度变化成本

4. **加加速度成本**：
   - `J_EGO_COST`：加加速度成本（舒适性）

5. **安全成本**：
   - `DANGER_ZONE_COST`：危险区域成本
   - `CRASH_DISTANCE`：碰撞距离阈值

#### 4.3.3 约束条件

**加速度约束**：
- 最小加速度：`ACCEL_MIN`（-4.0 m/s²）
- 最大加速度：根据速度动态调整

**安全约束**：
- 与前车保持安全距离
- 不超过巡航速度

#### 4.3.4 个性化设置

**三种个性模式**：

1. **Relaxed（放松）**：
   - 跟车距离：1.75秒
   - 加加速度因子：1.0

2. **Standard（标准）**：
   - 跟车距离：1.45秒
   - 加加速度因子：1.0

3. **Aggressive（激进）**：
   - 跟车距离：1.25秒
   - 加加速度因子：0.5

#### 4.3.5 前车处理

**前车模型**：
- 假设前车以恒定减速度减速
- 使用`_LEAD_ACCEL_TAU`时间常数

**安全距离计算**：
```python
safe_distance = (v_ego²) / (2 * COMFORT_BRAKE) + t_follow * v_ego + STOP_DISTANCE
```

### 4.4 输出发布

#### 4.4.1 纵向规划消息（longitudinalPlan）

**主要内容**：
- `speeds`：速度轨迹（CONTROL_N个点）
- `accels`：加速度轨迹
- `jers`：加加速度轨迹
- `t`：时间索引
- `fcw`：前向碰撞预警标志
- `solverExecutionTime`：求解器执行时间

#### 4.4.2 前向碰撞预警（FCW）

**触发条件**：
- MPC检测到碰撞风险（`crash_cnt > 2`）
- 车辆未静止

**处理**：
- 设置`fcw`标志
- 触发`EventName.fcw`事件

## 5. Card模块详细设计

### 5.1 模块概述

Card模块是车辆接口模块，负责CAN总线通信、车辆状态解析和控制命令发送。

**文件位置**：`selfdrive/car/card.py`

### 5.2 核心类：Car

#### 5.2.1 初始化（__init__）

**主要步骤**：

1. **消息通道设置**：
   ```python
   self.can_sock = messaging.sub_sock('can')
   self.sm = messaging.SubMaster(['pandaStates', 'carControl', ...])
   self.pm = messaging.PubMaster(['sendcan', 'carState', ...])
   ```

2. **车辆识别**：
   - 等待CAN消息
   - 调用`get_car()`识别车辆
   - 获取车辆接口（CarInterface）和参数（CarParams）

3. **参数配置**：
   - 设置替代体验标志
   - 检查控制器可用性
   - 设置被动模式（如果控制器不可用）

4. **保存车辆参数**：
   - 保存到`CarParams`
   - 保存到`CarParamsPersistent`
   - 保存到`CarParamsCache`

#### 5.2.2 状态更新（state_update）

**功能**：从CAN总线接收数据并更新车辆状态

**处理流程**：
1. **接收CAN消息**：
   ```python
   can_strs = messaging.drain_sock_raw(self.can_sock, wait_for_one=True)
   ```

2. **更新车辆状态**：
   ```python
   CS = self.CI.update(self.CC_prev, can_strs)
   ```
   - 解析CAN消息
   - 更新CarState
   - 检查CAN有效性

3. **更新SubMaster**：
   ```python
   self.sm.update(0)
   ```

4. **速度控制器更新**：
   ```python
   self.speed_controller.update_v_cruise(CS, self.sm, enabled)
   ```

#### 5.2.3 事件更新（update_events）

**功能**：根据车辆状态生成事件

**主要事件**：
- 从CarState中提取事件
- 处理加速器/制动器事件（如果启用）
- 注入速度控制器事件

#### 5.2.4 状态发布（state_publish）

**功能**：发布车辆状态和参数

**发布内容**：
1. **carParams**（每50秒）：
   - 车辆参数信息

2. **carOutput**：
   - 执行器输出状态
   - 用于控制验证

3. **carState**（每10ms）：
   - 车辆当前状态
   - CAN错误计数
   - 累积延迟

#### 5.2.5 控制更新（controls_update）

**功能**：将控制命令转换为CAN消息并发送

**处理流程**：
1. **初始化车辆接口**（首次）：
   ```python
   self.CI.init(self.CP, self.can_sock, self.pm.sock['sendcan'])
   ```

2. **生成CAN消息**：
   ```python
   self.last_actuators_output, can_sends = self.CI.apply(CC, now_nanos)
   ```
   - 将CarControl转换为车辆特定的CAN消息
   - 返回执行器输出状态

3. **速度控制器消息**：
   ```python
   self.speed_controller.spam_message(CS, can_sends)
   ```

4. **发送CAN消息**：
   ```python
   self.pm.send('sendcan', can_list_to_can_capnp(can_sends, ...))
   ```

#### 5.2.6 主循环（step）

**执行顺序**：
1. `state_update()`：更新车辆状态
2. `update_events()`：更新事件
3. `state_publish()`：发布状态
4. `controls_update()`：发送控制命令（如果已初始化且非被动模式）

**运行频率**：100Hz（10ms周期）

## 6. CarInterface模块详细设计

### 6.1 模块概述

CarInterface是车辆接口的抽象基类，定义了所有车辆品牌必须实现的接口。

**文件位置**：`selfdrive/car/interfaces.py`

### 6.2 核心类：CarInterfaceBase

- `VM`：车辆模型（VehicleModel）
- `CS`：车辆状态（CarState）
- `CC`：车辆控制器（CarController）
- CAN解析器：`cp`、`cp_cam`、`cp_adas`、`cp_body`、`cp_loopback`

#### 6.2.2 核心方法

**apply方法**：
```python
def apply(self, c: car.CarControl, now_nanos: int) -> tuple[car.CarControl.Actuators, list[SendCan]]:
    return self.CC.update(c, self.CS, now_nanos)
```
- 将CarControl转换为CAN消息
- 返回执行器输出和CAN消息列表

**update方法**：
```python
def update(self, c: car.CarControl, can_strings: list[bytes]) -> car.CarState:
```
- 解析CAN消息
- 更新车辆状态
- 返回CarState

**get_params方法**：
```python
@classmethod
def get_params(cls, candidate, fingerprint, car_fw, experimental_long, docs):
```

- 获取车辆参数
- 根据指纹和固件版本确定参数
- 返回CarParams

#### 6.2.3 车辆参数获取

#### 6.2.4 CAN消息解析

**解析器类型**：
- `cp`：动力总成CAN解析器
- `cp_cam`：摄像头CAN解析器
- `cp_adas`：ADAS CAN解析器

**解析流程**：
1. 接收CAN消息字符串
2. 转换为CAN消息列表

#### 6.2.5 控制命令生成

**CarController.update方法**：
- 接收CarControl和CarState

**CAN消息格式**：

## 7. RadarD模块详细设计

### 7.1 模块概述

RadarD模块负责融合雷达和摄像头数据，提供前车检测和跟踪功能。

**文件位置**：`selfdrive/controls/radard.py`

### 7.2 核心类：RadarD

#### 7.2.1 初始化

**主要组件**：
- `tracks`：雷达跟踪目标字典
- `kalman_params`：卡尔曼滤波器参数
- `v_ego`：自车速度
- `v_ego_hist`：自车速度历史（用于时间对齐）

#### 7.2.2 跟踪管理（Track类）

**状态变量**：
- `dRel`：相对距离
- `yRel`：横向相对位置
- `vRel`：相对速度
- `vLead`：前车速度
- `vLeadK`：卡尔曼滤波后的前车速度
- `aLeadK`：卡尔曼滤波后的前车加速度
- `aLeadTau`：加速度衰减时间常数

**卡尔曼滤波**：
- 状态：[速度, 加速度]
- 使用一维卡尔曼滤波器（KF1D）
- 根据雷达时间步长调整参数

**加速度学习**：
- 如果加速度较小（<0.5），使用标准时间常数
- 如果加速度较大，减小时间常数（更快衰减）

#### 7.2.3 更新流程（update）

**处理步骤**：
1. **接收雷达数据**：
   - 从RadarInterface获取雷达点
   - 提取距离、速度、横向位置等信息

2. **更新自车速度**：
   - 从carState获取当前速度
   - 保存到历史缓冲区（用于时间对齐）

3. **更新跟踪**：
   - 移除消失的跟踪目标
   - 创建新的跟踪目标
   - 更新现有跟踪目标的状态

4. **融合摄像头数据**：
   - 从modelV2获取摄像头检测的前车
   - 将雷达跟踪与摄像头检测匹配
   - 选择最佳前车

#### 7.2.4 前车选择（get_lead）

**选择逻辑**：
1. **摄像头优先**：
   - 如果摄像头检测到前车且置信度高，优先使用
   - 匹配最近的雷达跟踪

2. **雷达备用**：
   - 如果摄像头未检测到，使用雷达跟踪
   - 选择距离最近的有效跟踪

3. **低速处理**：
   - 低速时（<4 m/s），降低检测阈值
   - 避免误检静止物体

#### 7.2.5 输出发布

**radarState消息**：
- `leadOne`：第一前车（主要跟踪目标）
- `leadTwo`：第二前车（备用）
- `radarErrors`：雷达错误列表
- `cumLagMs`：累积延迟

**liveTracks消息**：
- 所有跟踪目标的详细信息
- 用于UI调试显示

### 7.3 雷达接口（RadarInterface）

**功能**：解析车辆特定的雷达CAN消息

**实现**：每个车辆品牌实现自己的RadarInterface
- 解析雷达CAN消息
- 转换为标准格式
- 返回雷达点列表
