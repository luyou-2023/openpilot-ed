# OpenPilot 系统架构文档

## 1. 概述

OpenPilot 是一个开源的自动驾驶辅助系统（ADAS），旨在为275+款支持的汽车提供驾驶辅助功能。本系统采用模块化架构，通过多个进程协同工作，实现从感知、规划到控制的完整自动驾驶流程。

### 1.1 系统特点

- **模块化设计**：各功能模块独立运行，通过消息队列通信
- **实时性**：关键控制模块运行在100Hz频率
- **安全性**：多层安全机制，包括Panda硬件安全层
- **可扩展性**：支持多种车型，通过CarInterface抽象层实现

### 1.2 技术栈

- **语言**：Python（主要）、C++（性能关键模块）
- **消息传递**：Cap'n Proto（cereal）
- **计算机视觉**：OpenCL/GPU加速的深度学习模型
- **硬件接口**：CAN总线通信（通过Panda设备）

## 2. 系统架构

### 2.1 整体架构图

```
┌─────────────────────────────────────────────────────────────┐
│                      Manager (进程管理器)                      │
│             负责启动、监控和管理所有子进程                        │
└─────────────────────────────────────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   System     │    │  Selfdrive   │    │   Hardware   │
│   Layer      │    │    Layer     │    │    Layer     │
└──────────────┘    └──────────────┘    └──────────────┘
```

### 2.2 分层架构

#### 2.2.1 System Layer（系统层）

负责系统级功能，包括：

- **camerad**：摄像头数据采集和处理
- **loggerd**：数据记录和日志管理
- **sensord**：传感器数据采集（IMU、GPS等）
- **locationd**：定位和导航
- **hardwared**：硬件管理
- **updated**：系统更新

#### 2.2.2 Selfdrive Layer（自动驾驶层）

核心自动驾驶功能模块：

- **modeld**：深度学习模型推理
- **controlsd**：控制决策和状态管理
- **plannerd**：路径和速度规划
- **radard**：雷达数据处理
- **card**：车辆接口和CAN通信
- **dmonitoringd**：驾驶员监控

#### 2.2.3 Hardware Layer（硬件层）

硬件抽象和接口：

- **pandad**：Panda设备通信（CAN总线）
- **hardware**：硬件抽象层

## 3. 核心模块

### 3.1 Manager（进程管理器）

**位置**：`system/manager/manager.py`

**职责**：
- 系统初始化（参数设置、设备注册）
- 进程生命周期管理（启动、监控、重启）
- 状态转换管理（onroad/offroad）
- 系统资源管理

**关键功能**：
- `manager_init()`：初始化系统参数和配置
- `manager_thread()`：主循环，监控所有进程状态
- `ensure_running()`：确保进程正常运行

### 3.2 Controls（控制系统）

**位置**：`selfdrive/controls/controlsd.py`

**职责**：
- 状态机管理（disabled/enabled/softDisabling等）
- 事件处理和警报管理
- 纵向和横向控制协调
- 控制命令生成和发布

**状态机**：
```
disabled → preEnabled → enabled
           ↓
      softDisabling → disabled
           ↓
      overriding → enabled
```

**关键组件**：
- `LongControl`：纵向控制（速度、加速度）
- `LatControl`：横向控制（转向）
- `AlertManager`：警报管理
- `Events`：事件系统

### 3.3 ModelD（模型推理）

**位置**：`selfdrive/modeld/modeld.py`

**职责**：
- 从摄像头获取图像数据
- 运行深度学习模型（Supercombo模型）
- 输出路径规划、车道线、目标检测等
- 发布模型推理结果

**模型输入**：
- 主摄像头图像
- 广角摄像头图像（可选）
- 历史特征缓冲区
- 期望动作（desire）
- 交通规则（左/右行）

**模型输出**：
- 路径规划（position, velocity, acceleration）
- 车道线检测
- 目标检测和跟踪
- 期望曲率（desired curvature）

### 3.4 PlannerD（规划器）

**位置**：`selfdrive/controls/plannerd.py`

**职责**：
- 纵向速度规划
- 跟车距离控制
- 碰撞预警（FCW）
- MPC（模型预测控制）优化

**关键算法**：
- `LongitudinalMpc`：纵向MPC控制器
- 速度轨迹优化
- 加速度限制（考虑横向加速度）

### 3.5 Card（车辆接口）

**位置**：`selfdrive/car/card.py`

**职责**：
- CAN总线数据接收和解析
- 车辆状态更新（CarState）
- 控制命令发送（CarControl → CAN消息）
- 车辆特定接口适配

**工作流程**：
1. 接收CAN消息 → 解析 → 更新CarState
2. 接收CarControl → 转换为CAN消息 → 发送

### 3.6 CarInterface（车辆接口抽象）

**位置**：`selfdrive/car/interfaces.py`

**职责**：
- 车辆品牌/型号特定实现
- CAN消息解析和生成
- 车辆参数配置
- 安全限制和验证

**支持的品牌**：
- Toyota, Honda, Hyundai, Ford, GM, Chrysler, Subaru, Nissan, Mazda, Tesla, Volkswagen等

## 4. 数据流

### 4.1 感知数据流

```
摄像头 → camerad → VisionIPC → modeld → modelV2消息
传感器 → sensord → sensorData消息
GPS → locationd → liveLocationKalman消息
```

### 4.2 控制数据流

```
modelV2 → plannerd → longitudinalPlan
modelV2 → controlsd → carControl
carControl → card → CAN消息 → 车辆执行器
```

### 4.3 状态反馈流

```
CAN总线 → card → carState
carState → controlsd → controlsState
controlsState → UI → 用户界面显示
```

## 5. 消息系统

### 5.1 消息格式

使用Cap'n Proto（cereal）进行消息序列化，支持：
- 类型安全
- 零拷贝
- 跨语言支持

### 5.2 关键消息类型

- **carState**：车辆状态（速度、转向角、按钮等）
- **carControl**：控制命令（转向、加速、制动）
- **modelV2**：模型推理结果
- **longitudinalPlan**：纵向规划结果
- **controlsState**：控制系统状态
- **deviceState**：设备状态（温度、存储等）

### 5.3 消息传递机制

- **PubMaster**：消息发布器
- **SubMaster**：消息订阅器
- **消息队列**：基于共享内存的高性能消息队列

## 6. 安全机制

### 6.1 Panda安全层

- 硬件级安全检查
- CAN消息验证
- 安全模式切换
- 故障检测和处理

### 6.2 软件安全

- 状态机验证
- 控制命令限制
- 超时检测
- 进程健康监控

### 6.3 故障处理

- 软禁用（Soft Disable）：给用户3秒时间接管
- 硬禁用（Hard Disable）：立即禁用系统
- 进程重启：自动重启崩溃的进程

## 7. 性能特性

### 7.1 实时性要求

- **controlsd**：100Hz（10ms周期）
- **card**：100Hz（10ms周期）
- **modeld**：20Hz（50ms周期）
- **plannerd**：20Hz（50ms周期）

### 7.2 优先级管理

使用Linux实时调度：
- CTRL_HIGH：控制关键进程
- CTRL_LOW：规划进程
- 其他：普通优先级

## 8. 配置和参数

### 8.1 参数存储

使用`Params`类管理持久化参数：
- 车辆参数（CarParams）
- 用户设置
- 校准数据
- 系统配置

### 8.2 车辆配置

每个支持的车型都有：
- 车辆参数文件（`values.py`）
- CAN消息定义（DBC文件）
- 接口实现（`interface.py`）
- 控制器实现（`carcontroller.py`）
- 状态解析器（`carstate.py`）

## 9. 扩展性

### 9.1 添加新车型

1. 创建车型目录（如`selfdrive/car/newbrand/`）
2. 实现`CarInterface`接口
3. 定义CAN消息解析器
4. 配置车辆参数
5. 测试和验证

### 9.2 添加新功能

- 通过消息系统扩展
- 添加新的进程模块
- 扩展控制算法

## 10. 总结

OpenPilot采用模块化、分层的架构设计，通过消息队列实现进程间通信，保证了系统的实时性、安全性和可扩展性。核心控制流程从感知到执行的完整链路清晰，便于理解和维护。
