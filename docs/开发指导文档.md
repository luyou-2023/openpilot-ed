## 第一部分：系统概述

### 1.1 OpenPilot 是什么？

OpenPilot 是 comma.ai 开发的开源驾驶辅助系统。它通过读取各种传感器数据（摄像头、IMU、转向角传感器、GNSS接收器等），处理这些数据并输入到大型神经网络，然后将神经网络的输出转换为车辆执行器可执行的控制命令。

**核心功能**：
- 车道保持（Lane Keeping）
- 自适应巡航控制（ACC）
- 驾驶员监控（Driver Monitoring）
- 自动紧急制动（AEB）

### 1.2 系统架构概览

OpenPilot 采用**发布/订阅消息系统**（基于 cereal 规范），各个服务通过消息队列进行通信。

### 1.3 服务分类

根据功能，OpenPilot 的服务可以分为以下几类：

1. **传感器和执行器（Sensors and Actuators）**
   - `camerad`：摄像头管理
   - `sensord`：传感器数据采集
   - `pandad`：Panda设备接口

2. **神经网络运行器（Neural Network Runners）**
   - `modeld`：主驾驶模型
   - `dmonitoringmodeld`：驾驶员监控模型
   - `dmonitoringd`：驾驶员监控逻辑

3. **定位和校准（Localization and Calibration）**
   - `ubloxd`：GNSS数据处理
   - `locationd`：车辆定位
   - `calibrationd`：摄像头校准
   - `paramsd`：车辆参数估计

4. **控制（Controls）**
   - `radard`：雷达数据处理
   - `plannerd`：路径规划
   - `controlsd`：控制执行
   - `card`：车辆接口

5. **系统、日志和其他（System, Logging, and Miscellaneous）**
   - `manager`：进程管理
   - `loggerd`：日志记录
   - `ui`：用户界面
   - `athenad`：云端连接

## 第二部分：核心服务详解

### 2.1 传感器和执行器服务

#### 2.1.1 camerad - 摄像头管理服务

**功能**：管理道路摄像头和驾驶员摄像头（comma three 还有额外的广角道路摄像头），处理自动对焦和自动曝光。

**代码位置**：
- 主入口：`system/camerad/main.cc`
- 核心实现：`system/camerad/cameras/`

**关键特性**：
1. **实时优先级**：优先级 53，绑定到 CPU 核心 6
2. **VisionIPC**：图像数据直接写入 VisionIPC，实现零拷贝传输
3. **多摄像头支持**：
   - 道路摄像头（road camera）
   - 驾驶员摄像头（driver camera）
   - 广角道路摄像头（wide road camera，仅 comma three）

**代码分析**：

```cpp
// system/camerad/main.cc
int main(int argc, char *argv[]) {
  // 设置实时优先级
  int ret = util::set_realtime_priority(53);
  assert(ret == 0);
  
  // 绑定到 CPU 核心 6
  ret = util::set_core_affinity({6});
  assert(ret == 0 || Params().getBool("IsOffroad"));
  
  // 启动摄像头线程
  camerad_thread();
  return 0;
}
```

**消息发布**：
- `roadCameraState`：道路摄像头状态（20Hz）
- `driverCameraState`：驾驶员摄像头状态（20Hz）
- `wideRoadCameraState`：广角道路摄像头状态（20Hz）

**开发要点**：
- 摄像头数据通过 VisionIPC 共享内存传递，避免数据拷贝
- 自动对焦和自动曝光算法在 `camerad` 中实现
- 图像格式为 YUV420，需要转换为模型输入格式

**消息发布**：

**开发要点**：
- 传感器数据需要校准和滤波
- 数据频率通常为 100Hz 或更高
- 传感器数据用于 `locationd` 的卡尔曼滤波

### 2.2 神经网络运行器服务

#### 2.2.1 modeld - 主驾驶模型服务

**功能**：读取 VisionIPC 的图像流，运行主驾驶神经网络（supercombo模型），预测驾驶路径、车道线、前车等信息。

**代码位置**：
- 主入口：`selfdrive/modeld/modeld.py`
- 模型运行器：`selfdrive/modeld/runners/`
- 输出解析：`selfdrive/modeld/parse_model_outputs.py`

**关键特性**：
1. **模型类型**：
   - Supercombo模型：端到端驾驶模型
   - 输出：路径规划、车道线、前车检测、道路边缘等

2. **输入数据**：
   - 图像数据（通过VisionIPC）
   - 历史状态（desire、traffic_convention等）
   - 车辆状态（carState）

3. **运行频率**：20Hz（50ms周期）

**代码分析**：

```python
# selfdrive/modeld/modeld.py
class ModelState:
    def __init__(self, context: CLContext):
        # 初始化模型
        self.model = ModelRunner(MODEL_PATHS, self.output, Runtime.GPU, False, context)
        
        # 准备输入数据
        self.inputs = {
            'desire': np.zeros(...),
            'traffic_convention': np.zeros(...),
            'lateral_control_params': np.zeros(...),
            'prev_desired_curv': np.zeros(...),
            'features_buffer': np.zeros(...),
        }
    
    def run(self, buf: VisionBuf, wbuf: VisionBuf, ...):
        # 设置输入缓冲区
        self.model.setInputBuffer("input_imgs", ...)
        
        # 执行模型推理
        self.model.execute()
        
        # 解析输出
        parsed_outputs = self.slice_outputs(self.output)
        return parsed_outputs
```

**消息订阅**：
- `roadCameraState`：道路摄像头图像
- `carState`：车辆状态
- `liveCalibration`：摄像头校准参数

**消息发布**：
- `modelV2`：模型输出（路径、车道线、前车等）
- `drivingModelData`：模型元数据
- `cameraOdometry`：视觉里程计

**开发要点**：
- 模型推理在GPU上执行，需要OpenCL或SNPE运行时
- 输入图像需要预处理（resize、normalize等）
- 模型输出需要解析（MDN、softmax、sigmoid等）
- 历史状态管理很重要，影响模型性能

#### 2.2.2 dmonitoringmodeld - 驾驶员监控模型服务

**功能**：运行驾驶员监控模型，使用驾驶员摄像头图像流，预测驾驶员头部姿态、眼睛开闭状态、是否佩戴太阳镜等。

**代码位置**：

**关键特性**：

   - 眼睛状态（开/闭）
   - 太阳镜检测

3. **运行频率**：20Hz

**消息订阅**：
- `driverCameraState`：驾驶员摄像头图像

**消息发布**：
- `driverStateV2`：驾驶员状态（头部姿态、眼睛状态等）

**开发要点**：

#### 2.2.3 dmonitoringd - 驾驶员监控逻辑服务

**功能**：评估驾驶员是否能够接管车辆，如果不能则发出警报。决策基于驾驶员监控模型输出、驾驶场景信息和一些参数。

**代码位置**：
- 主入口：`selfdrive/monitoring/dmonitoringd.py`
- 核心逻辑：`selfdrive/monitoring/helpers.py`

**关键特性**：
1. **注意力检测**：
   - 检测驾驶员是否分心
   - 检测驾驶员是否疲劳

2. **接管能力评估**：
   - 评估驾驶员是否能够接管
   - 基于头部姿态、眼睛状态、场景信息

3. **警报管理**：
   - 如果驾驶员分心，发出警报
   - 如果长时间分心，阻止启用openpilot

**代码分析**：

```python
# selfdrive/monitoring/dmonitoringd.py
def dmonitoringd_thread():
    # 初始化
    pm = messaging.PubMaster(['driverMonitoringState'])
    sm = messaging.SubMaster(['driverStateV2', 'liveCalibration', 'carState', 'controlsState', 'modelV2'], poll='driverStateV2')
    
    DM = DriverMonitoring(rhd_saved=params.get_bool("IsRhdDetected"), always_on=params.get_bool("AlwaysOnDM"))
    
    while True:
        sm.update()
        if not sm.updated['driverStateV2']:
            continue
        
        valid = sm.all_checks()
        if valid:
            DM.run_step(sm)  # 运行监控逻辑
        
        # 发布状态
        dat = DM.get_state_packet(valid=valid)
        pm.send('driverMonitoringState', dat)
```

**消息订阅**：
- `driverStateV2`：驾驶员状态（来自dmonitoringmodeld）
- `liveCalibration`：校准状态
- `carState`：车辆状态
- `controlsState`：控制状态
- `modelV2`：驾驶模型输出（用于场景理解）

**消息发布**：
- `driverMonitoringState`：驾驶员监控状态

**开发要点**：
- 驾驶员监控是安全关键功能，需要高可靠性
- 需要处理各种边缘情况（遮挡、光照变化等）
- 警报策略需要平衡安全性和用户体验

### 2.3 定位和校准服务

#### 2.3.1 ubloxd - GNSS数据处理服务

**功能**：解析GNSS数据，用于车辆定位。

**代码位置**：
- 主入口：`system/ubloxd/ubloxd.cc`
- 消息解析：`system/ubloxd/ublox_msg.cc`

**关键特性**：
1. **GNSS协议**：支持UBX协议（u-blox GNSS接收器）
2. **数据解析**：解析GNSS原始数据（位置、速度、时间等）
3. **消息格式**：使用Kaitai Struct定义消息格式

**消息发布**：
- `ubloxGnss`：GNSS数据（位置、速度、时间等）

**开发要点**：
- GNSS数据用于 `locationd` 的卡尔曼滤波
- 需要处理GNSS信号丢失的情况
- 数据频率通常为 10Hz

#### 2.3.2 locationd - 车辆定位服务

**功能**：负责车辆在世界坐标系中的定位。定位是准确描述车辆状态及其与世界交互的关键步骤。通过结合多个传感器的噪声数据，使用卡尔曼滤波器（live_kf）进行滤波，发布滤波后的值。

**代码位置**：
- 主入口：`selfdrive/locationd/locationd.cc`（C++实现）
- 卡尔曼滤波：`selfdrive/locationd/models/live_kf.py`

**关键特性**：
1. **多传感器融合**：
   - GNSS数据（来自ubloxd）
   - IMU数据（来自sensord）
   - 视觉里程计（来自modeld）

2. **卡尔曼滤波**：
   - 状态估计：位置、方向、速度、角速度、加速度
   - 噪声处理：处理传感器噪声和不确定性

3. **输出状态**：
   - 位置（position）
   - 方向（orientation）
   - 速度（velocity）
   - 角速度（angular velocity）
   - 加速度（acceleration）

**消息订阅**：
- `ubloxGnss`：GNSS数据
- `sensorEvents`：IMU数据
- `cameraOdometry`：视觉里程计

**消息发布**：
- `liveLocationKalman`：定位结果（位置、方向、速度等）
- `liveCalibration`：校准状态
- `liveParameters`：车辆参数

**开发要点**：
- 定位是控制算法的基础，需要高精度
- 卡尔曼滤波需要处理传感器失效的情况
- 需要处理GNSS信号丢失（隧道、城市峡谷等）

---

#### 2.3.3 calibrationd - 摄像头校准服务

**功能**：找到校准值，将神经网络驾驶模型的输入图像变换到校准坐标系，该坐标系与车辆的俯仰角和偏航角对齐。这可以标准化图像流，以处理人们在挡风玻璃上安装设备的各种方式。

#### 2.3.4 paramsd - 车辆参数估计服务

**功能**：估计车辆特定参数（质量、转向比、轮胎刚度、转向偏移、轮心到质心距离等），这些参数对于将驾驶路径转换为车辆理解的信号（如转向角）是必要的。

**代码位置**：
- 主入口：`selfdrive/locationd/paramsd.py`
- 卡尔曼滤波：`selfdrive/locationd/models/car_kf.py`

**关键特性**：
1. **估计参数**：
   - 转向比（steer ratio）
   - 轮胎刚度（tire stiffness）
   - 转向偏移（angle offset）
   - 质量（mass）
   - 其他车辆动力学参数

2. **估计方法**：
   - 使用单轨车辆模型
   - 卡尔曼滤波（car_kf）估计参数
   - 使用车辆运动数据（速度、角速度、转向角等）

**代码分析**：


**消息订阅**：
- `liveLocationKalman`：定位数据
- `carState`：车辆状态

**消息发布**：
- `liveParameters`：估计的车辆参数

**开发要点**：
- 参数估计需要车辆运动，静止时无法估计
- 参数估计是迭代过程，需要时间收敛
- 估计的参数用于控制算法，影响控制性能

### 2.4 控制服务

#### 2.4.1 radard - 雷达数据处理服务

**功能**：解释来自不同车型中各种雷达的原始数据，并将其转换为规范格式。

**代码位置**：
- 主入口：`selfdrive/controls/radard.py`

**关键特性**：
1. **雷达数据融合**：
   - 融合神经网络前车检测和雷达前车检测
   - 使用卡尔曼滤波跟踪前车

2. **前车跟踪**：

#### 2.4.2 plannerd - 路径规划服务

**功能**：规划分为两部分 - 横向规划（转向）和纵向规划（油门/制动）。两者都使用MPC（模型预测控制）求解器，确保规划平滑并优化合理的成本。

**代码位置**：
- 主入口：`selfdrive/controls/plannerd.py`
- 纵向规划：`selfdrive/controls/lib/longitudinal_planner.py`
- MPC实现：`selfdrive/controls/lib/longitudinal_mpc_lib/long_mpc.py`

**关键特性**：
1. **横向规划**：
   - 使用神经网络的路径预测
   - 有时使用车道线预测
   - 使用MPC求解器估计未来几秒内车辆应该转向多少（曲率）

2. **纵向规划**：
   - 主要依赖前车
   - 接收融合的前车估计（神经网络 + 雷达）和期望设定速度
   - 输入到MPC求解器，计算未来几秒的良好加速度曲线

**代码分析**：

```python

        self.mpc.set_cruise_speed(...)
```

```python
        # 初始化CAN套接字
        self.can_sock = messaging.sub_sock('can', timeout=20)
        self.sm = messaging.SubMaster(['pandaStates', 'carControl', ...])
        self.pm = messaging.PubMaster(['sendcan', 'carState', 'carParams', 'carOutput'])
        
        # 等待CAN消息，识别车辆
        if CI is None:
            get_one_can(self.can_sock)
            self.CI, self.CP = get_car(self.can_sock, self.pm.sock['sendcan'], ...)
    
    def state_update(self):
        # 接收CAN消息
        can_msgs = messaging.drain_sock(self.can_sock, wait_for_one=True)
        
        # 解析CAN消息
        self.CS = self.CI.update(self.CC_prev, can_msgs)
        
        # 发布carState
        self.pm.send('carState', self.CS.as_builder())
    
    def controls_update(self):
        # 接收carControl
        if self.sm.updated['carControl']:
            self.CC = self.sm['carControl']
            
            # 转换为CAN消息
            actuators = self.CI.create_actuators(self.CC, self.CS)
            can_sends = self.CI.apply(self.CC, actuators)
            
            # 发布sendcan
            self.pm.send('sendcan', can_sends)
```

## 第三部分：消息系统详解

### 3.1 消息系统架构

OpenPilot使用**发布/订阅消息系统**，基于以下技术：
- **Cap'n Proto**：消息序列化格式
- **msgq**：消息队列实现（基于共享内存）
- **cereal**：消息规范定义

**架构图**：

```
┌─────────────┐         ┌─────────────┐
│  Publisher  │────────▶│  消息队列   │
│  (PubMaster)│         │   (msgq)    │
└─────────────┘         └─────────────┘
                               │
                               ▼
                        ┌─────────────┐
                        │  Subscriber │
                        │ (SubMaster) │
                        └─────────────┘
```

### 3.2 消息格式

**Cap'n Proto定义**：
- 所有消息定义在`cereal/log.capnp`中
- 使用union类型定义不同的消息类型
- 所有消息都有`logMonoTime`和`valid`字段

**消息结构**：
```capnp
struct Event {
  logMonoTime @0 :UInt64;
  valid @1 :Bool;
  union {
    carState @2 :CarState;
    carControl @3 :CarControl;
    modelV2 @4 :ModelV2;
    # ... 更多消息类型
  }
}
```

### 3.3 PubMaster - 消息发布

**功能**：发布消息到消息队列

**代码位置**：`cereal/messaging/__init__.py`

**使用示例**：


**关键特性**：
- 支持发布多个消息类型
- 自动设置`logMonoTime`
- 零拷贝传输（共享内存）

### 3.4 SubMaster - 消息订阅

**功能**：订阅消息并检查消息有效性

**代码位置**：`cereal/messaging/__init__.py`

**使用示例**：

```python
# 创建SubMaster
sm = messaging.SubMaster(
    ['modelV2', 'carState', 'longitudinalPlan'],
    poll='modelV2',  # 主轮询消息
    ignore_alive=['testJoystick'],  # 忽略存活检查
    frequency=20  # 更新频率
)

while True:
    sm.update()  # 更新消息
    
    if sm.updated['modelV2']:
        # 检查所有消息是否有效
        if sm.all_checks():
            # 使用消息
            model = sm['modelV2']
            car_state = sm['carState']
            plan = sm['longitudinalPlan']
```

**关键特性**：
1. **消息检查**：
   - `updated`：消息是否更新
   - `alive`：消息源是否存活
   - `valid`：消息是否有效
   - `freq_ok`：消息频率是否正常

2. **轮询机制**：
   - 可以指定主轮询消息
   - 其他消息非阻塞接收

3. **消息验证**：
   - `all_checks()`：检查所有消息
   - `all_alive()`：检查所有消息源存活
   - `all_valid()`：检查所有消息有效

### 3.5 消息服务配置

**服务列表**：`cereal/services.py`

每个服务定义：
- 名称
- 是否记录
- 频率
- 降采样率

**示例**：


### 3.6 消息传递机制

**共享内存**：
- 消息存储在共享内存中（`/dev/shm`）
- 零拷贝传输，无数据复制
- 高性能，低延迟

**消息队列**：
- 每个消息类型有独立的队列
- 支持多个订阅者
- 自动处理消息过期

**开发要点**：
- 消息是系统解耦的关键
- 发布者不知道订阅者
- 消息格式变更需要保持向后兼容

### 5.1 控制循环完整路径

**从启动到控制的完整调用链**：

```
1. 系统启动
   launch_openpilot.sh
     → system/manager/manager.py::main()
       → manager_init()
       → manager_thread()
         → ensure_running()
           → 启动各个进程

2. controlsd启动
   selfdrive/controls/controlsd.py::main()
     → controlsd_thread()
       → Controls.__init__()
         → 初始化SubMaster/PubMaster
         → 初始化LongControl/LatControl
       → while True:
           Controls.step()
             → data_sample()      # 数据采样
             → update_events()    # 事件更新
             → state_transition()  # 状态转换
             → state_control()    # 控制计算
             → publish_logs()     # 发布日志
```

**关键函数调用链**：

```python
# 控制循环主路径
Controls.step()
  ├─ data_sample()
  │   └─ self.sm.update()  # 更新消息
  │   └─ self.sm['carState']  # 获取车辆状态
  │
  ├─ update_events(CS)
  │   └─ self.events.add(...)  # 添加事件
  │
  ├─ state_transition(CS)
  │   ├─ self.state = State.disabled/enabled/...
  │   └─ self.enabled = True/False
  │
  ├─ state_control(CS)
  │   ├─ self.LongControl.update(...)  # 纵向控制
  │   ├─ self.LatControl.update(...)  # 横向控制
  │   └─ return (CC, lac_log)
  │
  └─ publish_logs(CS, start_time, CC, lac_log)
      ├─ self.pm.send('controlsState', ...)
      ├─ self.pm.send('onroadEvents', ...)
      └─ self.pm.send('carControl', CC)
```

**从图像到模型输出的完整路径**：

```
1. 图像采集
   system/camerad/main.cc::main()
     → camerad_thread()
       → 采集图像
       → VisionIPC写入

2. 模型推理
   selfdrive/modeld/modeld.py::main()
```

```python
  ├─ self.frame.prepare(buf, transform, ...)  # 图像预处理

  └─ 填充元数据
```

### 5.3 CAN消息处理完整路径

**从控制命令到CAN总线的完整路径**：

```
1. 控制命令生成
   controlsd::state_control()
     → 计算控制命令
     → pm.send('carControl', CC)

2. CAN消息生成
   card::controls_update()
     → sm['carControl']
     → CI.apply(CC, actuators)
       → CarInterface.apply()
         → 品牌特定控制器
           → create_steer_command()
           → create_accel_command()
         → CAN消息打包
     → pm.send('sendcan', can_sends)

3. CAN消息发送
   pandad::main()
     → sm['sendcan']
     → panda.can_send_many(can_msgs)
       → CAN总线硬件
```

**关键函数调用链**：

```python
# CAN消息生成路径
Car.apply(CC, actuators)
  ├─ self.CI.apply(CC, actuators)
  │   ├─ 品牌特定控制器.apply()
  │   │   ├─ create_steer_command(...)
  │   │   ├─ create_accel_command(...)
  │   │   └─ create_brake_command(...)

  ├─ sm['sendcan']
  ├─ can_msgs = can_capnp_to_list(sendcan_msg)
  └─ panda.can_send_many(can_msgs)
```
