## 第一章：系统运行机制深度分析

### 1.1 系统启动：从进程管理到自动驾驶就绪

#### 1.1.1 Manager进程：系统的"大脑"

**核心文件**：`system/manager/manager.py`

**设计精髓**：Manager采用"进程工厂"模式，统一管理所有子进程的生命周期。

```python
def manager_thread() -> None:
  # 1. 订阅系统状态
  sm = messaging.SubMaster(['deviceState', 'carParams'], poll='deviceState')
  pm = messaging.PubMaster(['managerState'])
  
  # 2. 主循环：持续监控和协调
  while True:
    sm.update(1000)  # 等待系统状态更新
    
    started = sm['deviceState'].started  # 检测车辆是否启动
    
    # 3. 根据状态动态启动/停止进程
    ensure_running(managed_processes.values(), started, params=params, 
                   CP=sm['carParams'], not_run=ignore)
```

**关键设计点**：

1. **状态驱动架构**：
   - `deviceState.started`是系统的"心跳"
   - 所有进程的启动/停止都基于这个状态
   - 实现了"按需启动"，节省资源

2. **进程生命周期管理**：
```python
def ensure_running(procs, started, params, CP, not_run):
  for p in procs:
    # 判断进程是否应该运行
    if p.enabled and p.name not in not_run and p.should_run(started, params, CP):
      p.start()  # 启动
    else:
      p.stop(block=False)  # 停止
    
    p.check_watchdog(started)  # 看门狗检查
```

**设计精髓**：
- **看门狗机制**：每个进程都有独立的看门狗，超时自动重启
- **优雅降级**：进程崩溃不影响其他进程
- **状态同步**：所有进程状态通过`managerState`消息发布

#### 1.1.2 进程启动顺序：自动驾驶系统的"启动链"

**关键进程及其依赖关系**：

```
1. 基础进程（always_run）
   manager → ui → hardwared → pandad
   
2. 感知进程（onroad启动）
   camerad → modeld
   sensord → locationd
   
3. 控制进程（onroad启动，依赖感知）
   card → controlsd → plannerd
   radard → dmonitoringd
```

**代码实现**：`system/manager/process_config.py`


**设计精髓**：
- **条件启动函数**：每个进程都有`should_run`函数，决定是否启动
- **依赖隐式管理**：通过消息订阅实现依赖，而非显式依赖声明
- **故障隔离**：进程独立，一个崩溃不影响其他

### 1.2 消息系统：进程间的"神经网络"

#### 1.2.1 消息系统架构：零拷贝高性能通信

**核心文件**：`cereal/messaging/__init__.py`

**设计精髓**：基于共享内存的零拷贝消息传递

```python
class SubMaster:
  def __init__(self, services, poll=None, frequency=None):
    self.poller = Poller()  # 统一轮询器
    self.sock = {}
    
    for s in services:
      # 创建订阅socket（使用共享内存）
      self.sock[s] = sub_sock(s, poller=self.poller, conflate=True)
      
      # 初始化消息缓冲区
      self.data[s] = new_message(s)
```

**关键设计**：

1. **Conflate模式**：
```python
sub_sock(s, poller=self.poller, conflate=True)
```
- `conflate=True`：只保留最新消息，丢弃旧消息
- 适用于控制循环，避免处理过期数据
- 保证实时性

2. **统一轮询**：
```python
def update(self, timeout=1000):
  # 轮询所有socket，等待至少一个消息
  msgs = self.poller.poll(timeout)
  
  for s, msg in msgs:
    self.data[s] = log_from_bytes(msg)
    self.updated[s] = True
```

**设计精髓**：
- **阻塞式轮询**：`poll(timeout)`阻塞等待，避免CPU空转
- **批量更新**：一次轮询更新所有消息，保证数据一致性
- **时间戳同步**：所有消息都有`logMonoTime`，用于时间对齐

#### 1.2.2 消息流转：数据如何从传感器到执行器

**完整消息链路**：

```
1. 传感器数据采集
   camerad → VisionIPC → modeld订阅

2. 感知数据处理
   modeld → modelV2消息 → controlsd/plannerd订阅

3. 控制决策

4. 执行器控制

```

**发布端**（modeld）：

**订阅端**（controlsd）：

**设计精髓**：
- **发布订阅解耦**：发布者不知道订阅者，降低耦合
- **类型安全**：Cap'n Proto提供编译时类型检查
- **零拷贝**：共享内存传递，无需序列化/反序列化

### 1.3 控制循环：自动驾驶的"心脏"

#### 1.3.1 100Hz控制循环：实时性的保证

**核心文件**：`selfdrive/controls/controlsd.py`

**设计精髓**：固定频率执行，确保控制实时性

```python
def controlsd_thread(self):
  while True:
    self.step()  # 执行一步控制
    self.rk.monitor_time()  # 监控时间，确保100Hz
```

**Ratekeeper机制**：
```python
class Ratekeeper:
  def __init__(self, rate, print_delay_threshold=None):
    self.rate = rate  # 100Hz
    self.frame = 0
    self.last_monitor_time = time.monotonic()
  
  def monitor_time(self):
    # 计算应该休眠的时间
    self.remaining = (1.0 / self.rate) - (time.monotonic() - self.last_monitor_time)
    
    if self.remaining > 0:
      time.sleep(self.remaining)
    
    self.last_monitor_time = time.monotonic()
    self.frame += 1
```

**设计精髓**：
- **固定周期**：无论处理时间多长，都保证10ms周期
- **延迟监控**：`remaining < 0`表示延迟，触发警告
- **帧计数**：`frame`用于时间对齐和调试

#### 1.3.2 控制循环执行流程：从数据到决策

**step函数完整流程**：

```python
def step(self):
  # 1. 数据采样（10ms）
  CS = self.data_sample()  # 获取carState
  
  # 2. 事件更新（10ms）
  self.update_events(CS)  # 生成事件
  
  # 3. 状态转换（10ms）
  if not self.CP.passive and self.initialized:
    self.state_transition(CS)  # 更新状态机
  
  # 4. 控制计算（10ms）
  CC, lac_log = self.state_control(CS)  # 计算控制命令
  
  # 5. 发布日志（10ms）
  self.publish_logs(CS, start_time, CC, lac_log)  # 发布状态和控制
```

**时间分配**（典型值）：
- 数据采样：1-2ms
- 事件更新：1ms
- 状态转换：<1ms
- 控制计算：2-3ms（PID/MPC）
- 发布日志：1-2ms
- **总计**：5-9ms（留1-5ms余量）

**设计精髓**：
- **流水线设计**：每个步骤独立，可并行优化
- **时间预算**：严格控制每步时间，确保实时性
- **状态缓存**：`CS_prev`避免重复计算

### 1.4 状态机：自动驾驶的"决策大脑"

#### 1.4.1 状态机设计：安全第一

**状态定义**：
```python
State.disabled      # 禁用：系统不控制
State.preEnabled    # 预启用：准备启用
State.enabled       # 启用：系统控制中
State.softDisabling # 软禁用：给用户3秒接管
State.overriding    # 覆盖：用户正在控制
```

**状态转换逻辑**：

```python
def state_transition(self, CS):
  # 非禁用状态：检查禁用条件
  if self.state != State.disabled:
    # 用户禁用：立即禁用
    if self.events.contains(ET.USER_DISABLE):
      self.state = State.disabled
    
    # 立即禁用：硬件故障等
    elif self.events.contains(ET.IMMEDIATE_DISABLE):
      self.state = State.disabled
    
    # 软禁用：可恢复的问题
    elif self.events.contains(ET.SOFT_DISABLE):
      if self.state == State.enabled:
        self.state = State.softDisabling
        self.soft_disable_timer = int(SOFT_DISABLE_TIME / DT_CTRL)  # 3秒
  
  # 禁用状态：检查启用条件
  elif self.state == State.disabled:
    if self.events.contains(ET.ENABLE):
      if not self.events.contains(ET.NO_ENTRY):  # 无禁止条件
        self.state = State.enabled
```

**设计精髓**：

1. **优先级设计**：
   - `USER_DISABLE` > `IMMEDIATE_DISABLE` > `SOFT_DISABLE`
   - 用户意图最高优先级
   - 安全事件次之

2. **软禁用机制**：
```python
SOFT_DISABLE_TIME = 3  # 秒

# 软禁用中
elif self.state == State.softDisabling:
  if not self.events.contains(ET.SOFT_DISABLE):
    self.state = State.enabled  # 问题解决，恢复启用
  elif self.soft_disable_timer <= 0:
    self.state = State.disabled  # 超时，禁用
```

**设计精髓**：
- **给用户时间**：3秒让用户接管，避免突然禁用
- **自动恢复**：问题解决后自动恢复
- **渐进式降级**：enabled → softDisabling → disabled

#### 1.4.2 事件系统：状态转换的触发器

**事件类型**：
```python
ET.NO_ENTRY          # 禁止进入：系统不可用
ET.SOFT_DISABLE      # 软禁用：可恢复问题
ET.IMMEDIATE_DISABLE # 立即禁用：严重问题
ET.USER_DISABLE      # 用户禁用：用户操作
ET.PRE_ENABLE        # 预启用：需要准备
ET.ENABLE            # 启用：可以启用
ET.WARNING           # 警告：不影响控制
```

**事件生成**：

```python
def update_events(self, CS):
  self.events.clear()
  
  # 硬件故障事件
  if not self.sm.all_alive(self.camera_packets):
    self.events.add(EventName.cameraMalfunction)  # → SOFT_DISABLE
  
  if not self.sm.valid['pandaStates']:
    self.events.add(EventName.usbError)  # → IMMEDIATE_DISABLE
  
  # 车辆状态事件
  if CS.canTimeout:
    self.events.add(EventName.canBusMissing)  # → IMMEDIATE_DISABLE
  
  # 系统状态事件
  if self.sm['deviceState'].thermalStatus >= ThermalStatus.red:
    self.events.add(EventName.overheat)  # → SOFT_DISABLE
```

**设计精髓**：
- **事件驱动**：所有状态转换都由事件触发
- **事件优先级**：事件有优先级，高优先级覆盖低优先级
- **事件组合**：多个事件可以同时存在，状态机综合判断

### 1.5 系统运行总结

**核心运行机制**：

1. **Manager协调**：
   - 监控系统状态
   - 动态启动/停止进程
   - 看门狗监控

2. **消息驱动**：
   - 进程间通过消息通信
   - 零拷贝高性能
   - 发布订阅解耦

3. **控制循环**：
   - 100Hz固定频率
   - 数据→事件→状态→控制→发布
   - 严格时间控制

4. **状态机决策**：
   - 事件驱动状态转换
   - 安全优先
   - 渐进式降级

**系统运行流程图**：

```
Manager启动
  ↓
检测deviceState.started
  ↓
启动感知进程（camerad, modeld, sensord）
  ↓
启动控制进程（card, controlsd, plannerd）
  ↓
controlsd进入100Hz循环：
  数据采样 → 事件更新 → 状态转换 → 控制计算 → 发布
  ↓
card接收carControl → 生成CAN消息 → 发送到车辆
```

### 2.2 PlannerD模块：从模型到速度规划

#### 2.2.1 输入分析：模型输出的利用

**输入来源**：

1. **modelV2消息**：
```python
# selfdrive/controls/plannerd.py
sm = SubMaster(['modelV2', 'carState', 'controlsState', 'radarState'])

# 解析模型输出
x, v, a, j = LongitudinalPlanner.parse_model(sm['modelV2'], v_model_error)
```

**parse_model函数**：
```python
@staticmethod
def parse_model(model_msg, model_error):
  # 从modelV2提取路径规划
  x = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.position.x) - model_error * T_IDXS_MPC
  v = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.velocity.x) - model_error
  a = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.acceleration.x)
  
  return x, v, a, j
```

### 3.1 消息系统：进程间的"粘合剂"

#### 3.1.1 共享内存机制：零拷贝通信

**核心实现**：`msgq/ipc_pyx.pyx`（Cython扩展）

**设计精髓**：基于POSIX共享内存的高性能IPC

```python
# 共享内存创建
class Context:
  def __init__(self):
    self.context = ipc_context_create()  # C实现
    
  def create_socket(self, name, mode):
    # 创建共享内存区域
    shm_fd = shm_open(name, O_CREAT | O_RDWR, 0666)
    ftruncate(shm_fd, size)
    
    # 内存映射
    mmap(addr, size, PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd, 0)
```

**关键设计**：

1. **命名空间管理**：
```python
# 每个消息类型有唯一的socket名称
socket_name = f"/tmp/msgq_{service_name}"
```

2. **环形缓冲区**：
```python
# 使用环形缓冲区实现FIFO队列
class RingBuffer:
  def __init__(self, size):
    self.buffer = mmap(size)  # 共享内存
    self.write_pos = 0
    self.read_pos = 0
```

**设计精髓**：
- **零拷贝**：数据直接在共享内存中，无需复制
- **无锁设计**：使用原子操作，避免锁竞争
- **高吞吐**：适合高频消息传递

#### 3.1.2 发布订阅模式：解耦设计

**PubMaster实现**：
```python
class PubMaster:
  def __init__(self, services):
    self.sock = {}
    for s in services:
      self.sock[s] = pub_sock(s)  # 创建发布socket
  
  def send(self, service, msg):
    # 序列化消息
    data = msg.to_bytes()
    
    # 发送到共享内存
    self.sock[service].send(data)
```

**SubMaster实现**：
```python
class SubMaster:
  def __init__(self, services, poll=None):
    self.poller = Poller()
    self.sock = {}
    
    for s in services:
      # 创建订阅socket（conflate模式）
      self.sock[s] = sub_sock(s, poller=self.poller, conflate=True)
  
  def update(self, timeout=1000):
    # 轮询所有socket
    msgs = self.poller.poll(timeout)
    
    for s, data in msgs:
      # 反序列化（零拷贝，直接访问共享内存）
      self.data[s] = log_from_bytes(data)
      self.updated[s] = True
```

**设计精髓**：

1. **Conflate模式**：
```python
conflate=True  # 只保留最新消息
```
- 丢弃旧消息，保证实时性
- 适用于控制循环，避免处理过期数据

2. **统一轮询**：
```python
self.poller.poll(timeout)  # 阻塞等待
```
- 一次轮询获取所有新消息
- 保证数据时间一致性

3. **消息验证**：
```python
def all_checks(self):
  return all(self.valid[s] for s in self.data.keys() 
             if s not in self.ignore_valid)
```
- 检查消息有效性
- 用于系统健康监控

```python
def ensure_running(procs, started, params, CP, not_run):
  for p in procs:
    # 判断是否应该运行
    should_run = p.enabled and p.name not in not_run and \
                 p.should_run(started, params, CP)
    
    if p.proc is not None:
      if not p.proc.is_alive():
        # 进程已死，重启
        p.restart()
      elif not should_run:
        # 不应该运行，停止
        p.stop(block=False)
    else:
      if should_run:
        # 应该运行但未运行，启动
        p.start()
    
    # 看门狗检查
    p.check_watchdog(started)
```

#### 4.1.2 期望动作输入：人机交互的桥梁

**输入来源**：DesireHelper（基于用户操作和模型预测）

**DesireHelper工作原理**：
```python
# selfdrive/controls/lib/desire_helper.py
class DesireHelper:
  def update(self, carstate, lateral_active, lane_change_prob):
    # 1. 检测转向灯
    one_blinker = carstate.leftBlinker != carstate.rightBlinker
    
    # 2. 状态机管理车道变更
    if self.lane_change_state == LaneChangeState.off:
      if one_blinker and not self.prev_one_blinker:
        self.lane_change_state = LaneChangeState.preLaneChange
    
    # 3. 生成期望动作
    self.desire = DESIRES[self.lane_change_direction][self.lane_change_state]
```

**期望动作类型**：
```python
DESIRES = {
  LaneChangeDirection.none: {
    LaneChangeState.off: log.Desire.none,
    LaneChangeState.preLaneChange: log.Desire.none,
    LaneChangeState.laneChangeStarting: log.Desire.laneChangeLeft,
    ...
  },
  LaneChangeDirection.left: {
    LaneChangeState.laneChangeStarting: log.Desire.laneChangeLeft,
    ...
  },
  ...
}
```

**期望动作处理**（脉冲触发）：
```python
# ModelState.run()
# 1. 准备期望动作向量
vec_desire = np.zeros(ModelConstants.DESIRE_LEN, dtype=np.float32)
if desire >= 0 and desire < ModelConstants.DESIRE_LEN:
  vec_desire[desire] = 1

# 2. 脉冲触发处理
inputs['desire'][0] = 0  # 当前帧清零
# 历史缓冲区右移
self.inputs['desire'][:-ModelConstants.DESIRE_LEN] = \
  self.inputs['desire'][ModelConstants.DESIRE_LEN:]
# 检测上升沿，只在动作开始时发送
self.inputs['desire'][-ModelConstants.DESIRE_LEN:] = np.where(
  inputs['desire'] - self.prev_desire > .99, 
  inputs['desire'], 
  0
)
self.prev_desire[:] = inputs['desire']
```

**设计精髓**：
- **脉冲触发**：只在动作开始时发送，模型决定完成时间
- **历史缓冲**：5秒历史（100帧），提供上下文
- **人机协作**：用户意图（转向灯）→ 期望动作 → 模型执行

**输入作用**：
- 告诉模型用户意图（变道、转向等）
- 模型根据意图调整路径规划
- 实现人机协作驾驶

```python
def slice_outputs(self, model_outputs):
  # 根据元数据切片
  parsed = {
    k: model_outputs[np.newaxis, v] 
    for k, v in self.output_slices.items()
  }
  return parsed
```

**parse_outputs**：
```python
def parse_outputs(self, outs):
  # 1. 解析MDN输出（路径、车道线等）
  self.parse_mdn('plan', outs, ...)
  self.parse_mdn('lane_lines', outs, ...)
  self.parse_mdn('lead', outs, ...)
  
  # 2. 解析概率输出
  self.parse_binary_crossentropy('lead_prob', outs)
  self.parse_binary_crossentropy('lane_lines_prob', outs)
  
  # 3. 解析分类输出
  self.parse_categorical_crossentropy('desire_state', outs)
  
  return outs
```

```python
def can_list_to_can_capnp(can_list, msgtype='sendcan', valid=True):
  msg = messaging.new_message(msgtype, len(can_list))
  msg.valid = valid
  
  for i, (addr, dat, bus) in enumerate(can_list):
```

**LongitudinalPlanner工作流程**：

**模型解析**：

```python
@staticmethod
def parse_model(model_msg, model_error):
  # 从模型输出提取位置、速度、加速度
  x = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.position.x) - model_error * T_IDXS_MPC
  v = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.velocity.x) - model_error
  a = np.interp(T_IDXS_MPC, ModelConstants.T_IDXS, model_msg.acceleration.x)
  j = np.zeros(len(T_IDXS_MPC))  # 加加速度（jerk）
  return x, v, a, j
```

**设计精髓**：
- **速度误差补偿**：`model_error`补偿模型预测速度与实际速度的误差
- **时间索引对齐**：从模型时间索引（33点）插值到MPC时间索引（16点）
- **加加速度平滑**：考虑jerk，保证加速度变化平滑

#### 6.1.2 MPC优化：多目标权衡

**MPC优化目标**：

1. **跟踪巡航速度**：
```python

```

2. **跟踪模型路径**：
```python

```

3. **最小化加速度变化**：
```python
# 目标：最小化jerk，保证舒适性

```

4. **保持安全距离**：
```python
# 约束：x[i] >= lead_x[i] + safe_distance
if has_lead:
  constraints.append(x[i] >= lead_x[i] + desired_follow_distance(v[i], lead_v[i]))
```

```python
def limit_accel_in_turns(v_ego, angle_steers, a_target, CP):
  # 计算横向加速度
  a_y = v_ego^2 * angle_steers * DEG_TO_RAD / (steerRatio * wheelbase)
  
  # 总加速度限制
  a_total_max = interp(v_ego, [20, 40], [1.7, 3.2])
  
  # 纵向加速度限制
  a_x_allowed = sqrt(max(a_total_max^2 - a_y^2, 0))
  
  return min(a_target, a_x_allowed)
```

**设计精髓**：
- **速度自适应**：高速时降低加速度，保证安全
- **转弯保护**：转弯时限制纵向加速度，避免侧滑
- **总加速度限制**：保证总加速度不超过轮胎极限

```python
class LatControlPID(LatControl):
  def update(self, active, CS, VM, lat_plan, steer_limited, desired_curvature, llk):
    if not active:
      return 0.0, 0.0, pid_log
    
    # 1. 曲率转角度

      VM.get_steer_from_curvature(-desired_curvature, CS.vEgo, llk.roll)
```

```python
  def run(self, x0, p, y_pts, heading_pts, yaw_rate_pts):
    # 1. 设置初始状态
    self.solver.constraints_set(0, "lbx", x0)
    self.solver.constraints_set(0, "ubx", x0)
    
    # 2. 设置参考轨迹
    self.yref[:,0] = y_pts  # 横向位置
    self.yref[:,1] = heading_pts * (v_ego + SPEED_OFFSET)  # 航向角
    self.yref[:,2] = yaw_rate_pts * (v_ego + SPEED_OFFSET)  # 横摆角速度
    
    # 3. 设置参数（速度）
    for i in range(N):
      self.solver.set(i, "p", p[i])
    
    # 4. 求解
    self.solver.solve()
    
    # 5. 提取解
    self.x_sol = self.solver.get_x_solution()
    self.u_sol = self.solver.get_u_solution()
```

```python
# 成本项

```

**设计精髓**：
